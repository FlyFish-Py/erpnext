# 需求：新账号默认密码与首次登录强制改密

| 项目 | 内容 |
|---|---|
| 需求编号 | REQ-001 |
| 提出日期 | 2026-07-03 |
| 提出人 | Gary |
| 状态 | ✅ 已验收通过（2026-07-03，Gary 确认） |
| 承载 | 自定义应用 `mingda`（本需求起新建） |

## 1. 需求描述

1. **所有账号**（系统用户 + 门户用户）在创建时自动设置默认密码 `123456`，不再依赖欢迎邮件让用户自设密码。
2. 用户**首次登录后必须强制修改密码**，未改密前不允许使用系统其他功能。
3. 创建用户时**不再发送欢迎邮件**（初始密码由管理员线下告知）。

## 2. 需求确认记录（2026-07-03 与 Gary 确认）

| 决策点 | 结论 |
|---|---|
| 适用范围 | 所有用户（含门户账号），Administrator/Guest 除外 |
| 欢迎邮件 | 不发送 |
| 周期性强制改密 | 不需要（不启用系统自带的"每 N 天改密"） |
| 实现位置 | 新建独立自定义 App，不改 erpnext/frappe 核心 |

## 3. 验收标准

- [x] 新建任意用户（不设密码、不发邮件），能直接用 `账号 + 123456` 登录
- [x] 首次登录后立即被带到改密页面，改密前访问其他页面会被拦回
- [x] 新密码需符合系统密码强度策略；修改成功后正常使用系统
- [x] 第二次登录不再被强制改密
- [x] 管理员手动给用户改密码后，该用户同样不再被强制改密
- [x] Administrator 自身不受影响
- [x] 已存在的老用户不受影响（机制只作用于启用后新建的账号）

> 验收过程中发现并修复 [BUG-001](../bugfixes/2026-07-03-BUG-001-install-patch-not-run.md)、[BUG-002](../bugfixes/2026-07-03-BUG-002-redirect-uncaught-exception.md)。

## 4. 风险与说明

- 默认密码 `123456` 是公开约定，**系统已暴露公网**：知道某员工邮箱的人可在其首次登录前抢先登录。缓解：管理员建号后应提醒员工尽快首次登录；默认密码可通过服务器配置（`site_config.json` 的 `mingda_default_password`）随时更换，无需改代码。
- 相关技术方案见 [technical/2026-07-03-default-password-policy.md](../technical/2026-07-03-default-password-policy.md)。
